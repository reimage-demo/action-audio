# Action Audio — Public website

Live site: https://www.actionaudiostorellc.com/

Public landing page for QR codes: https://www.actionaudiostorellc.com/landing-page.html

Source lives on main; GitHub Pages serves the compiled gh-pages branch.

## Local development and builds

```sh
npm ci
cp .env.example .env.local
npm run dev
# Build the deployable files:
npm run build
```

Publish only the contents of dist to the gh-pages branch. Never publish local environment or credential files.

Both live sites use the Action Audio production deployment standing-elephant-145. Local development can use robust-stork-24; do not point routine development or tests at production. Wethersfield handles electronics and remote starters; Hartford handles detailing and window tinting. The booking API enforces these specialties. Customer tracking has four staff-confirmed stages with optional, explicitly labeled daily estimates capped within the current stage. Staff set statuses, customer notes, and target pickup dates in the appointment dialog. The Estimates tab receives service-specific customer requests with name, phone, vehicle year/make/model, service-specific answers, project details, and optional trim/budget/timing; the manager can call and record quotes. Deploy the updated Convex functions before the frontends when releasing new intake fields or booking categories. Exactly one manager login is supported, with no public signup or staff-account creation. The public electronics page uses labeled example models and original category illustrations. The design uses a white, deep blue (#12345B), and red (#C92336) palette. The header/footer are blue, the home services band is red, and the full-width photographic slideshow carries overlaid text. Four services are featured with nine more in an accessible disclosure; all thirteen have dedicated pages and estimate links. The admin uses the public palette with navy navigation and panel headers, red primary actions, and white content surfaces. Typography is self-hosted IBM Plex Sans. Images are original illustrations and retouched showroom photographs. Responsive AVIF/WebP variants are generated by npm run images:optimize; run it after replacing original WebP assets. Hero photos fill the entire slideshow using higher-quality responsive exports, lower-page images load lazily, and the next slideshow image is decoded before switching. Booking and estimate forms give immediate pending feedback, preserve details on failure, and confirm success only after server acknowledgement. Enable HTTPS enforcement after GitHub provisions the custom-domain certificate. Staff authentication and customer data remain on Convex; no passwords or customer records are stored in this repository.

## Search content update — October 30, 2026

The public site targets car detailing in Hartford, CT (interior and exterior care) and car audio/electronics installation in Wethersfield, CT (stereos, speakers, amplifiers, subwoofers, remote starters, dash cams, and replacement equipment). Keyword choices are based on service relevance and observed local search-result wording, not paid search-volume estimates. Do not add mobile detailing, ceramic coating, paint correction, electronics repair, or guaranteed pricing without business confirmation.

`shared/search-content.js` holds the service planning guides and page FAQs. The same answers feed visible HTML, JSON-LD, and `llms-full.txt`. All 13 service pages have descriptive, localized H1s and distinct titles/descriptions. Canonical URLs and schema IDs use `https://www.actionaudiostorellc.com/`. `scripts/build.mjs` regenerates pages and discovery files automatically before copying them, preventing outdated source metadata from leaking into releases. Sitemap modification dates use the explicit substantive-review date in `scripts/seo.mjs` or a page-specific `updated` date; do not replace these with the current build time. Tracking and retired-service pages remain outside the sitemap.

Validation covers all 26 indexable pages, unique metadata, one H1 per page, store/service matching, same-origin structured data, visible FAQs, internal links, image alternatives, dated sitemap entries, and AI reference consistency. `llms.txt` is a supplementary reference, not a Google ranking requirement. GitHub Pages does not support arbitrary HTTP response-header configuration; canonical, robots and preview controls are delivered in HTML, and TLS is handled by GitHub.
